# KaamSetu – Deployment Checklist (Vercel & Render)

This document provides the exact, production-verified step-by-step procedure to deploy the KaamSetu full-stack monorepo to Render (Backend API + Managed PostgreSQL) and Vercel (Next.js 14 Frontend).

---

## Architecture Overview

```
[Customer Browser / Mobile]
          │
          ├── HTTPS ──> Vercel Edge Network (Next.js 14 App Router: /web)
          │               └── Rewrites: /api/* ──> Render API (preserves First-Party Cookies)
          │
          └── HTTPS / SSE (EventSource) ──> Render Web Service (Express API: /server)
                                              └── Prisma ORM ──> Render Managed PostgreSQL
```

---

## Step 1: Create Render PostgreSQL Database

1. Log into your [Render Dashboard](https://dashboard.render.com).
2. Click **New +** -> **PostgreSQL**.
3. Configure the database:
   - **Name**: `kaamsetu-postgres`
   - **Database**: `kaamsetu`
   - **User**: `kaamsetu_user`
   - **Region**: Choose the region closest to your users (e.g. `Oregon` or `Frankfurt`).
   - **Plan**: `Free`
4. Once provisioned, copy the **Internal Database URL** (for the Render server service) and the **External Database URL** (for running local migrations if needed).

---

## Step 2: Deploy Backend Server to Render

1. Click **New +** -> **Web Service**.
2. Connect your GitHub repository containing `kaamsetu`.
3. Configure service settings:
   - **Name**: `kaamsetu-api`
   - **Region**: Same region as the database
   - **Root Directory**: `server`
   - **Runtime**: `Node`
   - **Build Command**:
     ```bash
     npm ci && npx prisma generate && npm run build
     ```
   - **Start Command**:
     ```bash
     npx prisma migrate deploy && npm run seed && node dist/index.js
     ```
   - **Health Check Path**: `/api/health`
4. In the **Environment Variables** section, add:
   - `NODE_ENV`: `production`
   - `PORT`: `10000`
   - `DATABASE_URL`: *(Select "Add from Database" -> choose `kaamsetu-postgres` or paste the Internal URL)*
   - `JWT_ACCESS_SECRET`: *(Click "Generate" or paste a 64-character random string)*
   - `JWT_REFRESH_SECRET`: *(Click "Generate" or paste a 64-character random string)*
   - `COOKIE_DOMAIN`: Leave empty if using Next.js proxy rewrites, or set to `.yourdomain.com` if using a shared custom domain.
   - `MSG91_AUTH_KEY`: *(Your MSG91 SMS Auth Key)*
   - `MSG91_TEMPLATE_ID`: *(Your approved DLT OTP Template ID)*
   - `RESEND_API_KEY`: *(Your Resend API Key)*
   - `MAIL_FROM`: `KaamSetu <noreply@yourdomain.com>`
   - `CLOUDINARY_CLOUD_NAME`: *(Your Cloudinary cloud name)*
   - `CLOUDINARY_API_KEY`: *(Your Cloudinary API key)*
   - `CLOUDINARY_API_SECRET`: *(Your Cloudinary API secret)*
   - `ADMIN_EMAIL`: `nikaleajay3@gmail.com`
   - `ADMIN_PHONE`: `7875453977`
5. Click **Create Web Service**.
6. Note the public URL generated by Render (e.g., `https://kaamsetu-api.onrender.com`).

## Step 3: Deploy Frontend to Vercel

1. Log into your [Vercel Dashboard](https://vercel.com).
2. Click **Add New...** -> **Project** -> Import your GitHub repository.
3. Configure the project:
   - **Framework Preset**: `Next.js`
   - **Root Directory**: Click "Edit" and select `web`.
4. In **Environment Variables**, supply:
   - `NEXT_PUBLIC_API_URL`: Your Render API URL (e.g., `https://kaamsetu-api.onrender.com`)
   - `CORE_API_URL`: Your Render API URL (e.g., `https://kaamsetu-api.onrender.com`)
   - `NEXT_PUBLIC_SITE_URL`: Your Vercel domain (e.g., `https://kaamsetu.vercel.app`)
   - `NEXT_PUBLIC_DEFAULT_LOCALE`: `en`
5. Verify `vercel.json` in the repository root or web root to ensure the rewrite rule directs `/api/:path*` to your Render API.
6. Click **Deploy**. Note your Vercel deployment URL (e.g., `https://kaamsetu.vercel.app`).

---

## Step 4: Configure CORS & Web Origin on Render

1. Return to your `kaamsetu-api` service in the Render Dashboard.
2. Under **Environment**, set:
   - `WEB_ORIGIN`: Your Vercel frontend URL (e.g., `https://kaamsetu.vercel.app`)
3. Click **Save Changes**. Render will automatically trigger a rolling redeployment with CORS headers strictly locked to your Vercel origin.
